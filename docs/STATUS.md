## 1. 当前功能

### 查询与展示

- 按注册号 / 航司 / 机型 / 联盟自由文本搜索（前端纯 JS，全量加载后即时匹配）
- 顶部 4 个筛选下拉：地区 / 联盟 / 登记与资料匹配 / 类别
- 卡片信息：机型 + 航司 + 联盟徽章 + 登记状态 + 出厂/登记/注销日期 + 序列号 + ICAO24
- 客舱比例条（F/C/W/Y 彩色 + 图例）
- 飞机照片（懒加载 + 摄影师署名）
- 跳转到飞行追踪、已核实的座位图或照片库
- 移动端优先布局，明/暗模式自适应

### 数据源

- **OpenSky Network** 最新可用公开飞机快照 —— 主源（当前上游最新为 2025-08）
- **tar1090-db / Mictronics** 按注册号和六位地址补充飞机资料
- **FAA 和澳门民航局** 核查机身身份、注销、号码复用及澳门运营人
- **Planespotters Photo API** —— 飞机照片（含署名）
- **手工维护** 航司 / 机型 / 客舱布局映射

### 登记和机型核验

合并时先规范化注册号，再按六位地址关联。FAA 更正按机身序列号适用。地址或机型仍冲突时显示待核实并暂缓关联客舱。登记注销以 FAA 历史登记为依据。

### 自动化

- **GitHub Actions** 每月 5 日 03:30 UTC 自动拉数据 → 构建 → 提交 → 部署
- 每次 push 到 main 自动触发 GH Pages 部署

## 2. 架构

### 数据流

```
OpenSky CSV + tar1090 CSV
             │
             ├── 航司与机型字典、登记更正、客舱和座位图目录
             ▼
scripts/build_data.py ──> 行式与列式飞机数据、客舱查询表、数据版本
```

前端一次加载飞机数据并在本地搜索。照片按需调用 API。

### 关键设计决定

| 决定 | 理由 |
| --- | --- |
| 纯静态托管 | 约 57k 条列存数据在浏览器里跑得动；GH Pages 免费；零运维 |
| 选 OpenSky 作主源 | 完全免费、全球覆盖、含 `regUntil` 等历史字段、无 API key |
| 使用 tar1090 元数据库 | 缺资料时按同一注册号和六位地址补充，并标记快照是否匹配 |
| 不存任何用户数据 | 全部前端，零合规负担 |
| 客舱用比例条而非真实座位图 | 真实座位图无开源数据集，比例条 + 跳转链接是平衡解 |
| 不抓取第三方网站 | 所有第三方仅做 deep-link 或调用公开 API |

## 3. 已知局限

| 问题 | 影响范围 | 现状 |
| --- | --- | --- |
| OpenSky 快照发布不规律，当前最新仍为 2025-08 | 全球 | GH Actions 每月检查最新快照，并用最新 tar1090 快照补充资料 |
| 客舱布局以 (航司, 机型) 为粒度，但同一对常有多种实际配置 | 全球 | 已核实的版本写入 `notes`，可通过报错入口补充证据 |
| 部分注册号 operator 字段缺失 | 全球 | 同号同机型的照片可作为航司线索 |
| 登记状态和实时飞行状态各有独立来源 | 全球 | 页面分别提供登记核验结论和飞行追踪入口 |
| 已识别航司的商用飞机中，70.7% 有航司专属客舱 | 全球 | 20,067 / 28,400 条 |

### 覆盖范围限制

- 私人 / 通用航空 / 军用机 不在白名单（中国大陆/港/澳/台 B- 注册号宽松保留）
- 照片依赖 Planespotters 收录范围
- 座位图入口使用经过核实的链接目录

### 前端

- 优先加载 7.6 MiB 的列式文件，行式兼容文件约 23.4 MiB
- 搜索结果最多显示 80 条
- 已支持 `/` 聚焦、`Esc` 清空、航司拼音搜索和最近 10 条查询

## 4. 改进方向（roadmap）

### 短期（小工作量，高价值）

- [x] **PWA / 离线**：service worker 缓存页面与按内容版本读取的数据，联网时优先更新版本清单
- [x] **拼音搜索**：构建时用 `pypinyin` 给每个航司中文名生成全拼 + 首字母（`gh` / `guohang` 都能匹配国航）
- [x] **机龄显示**：基于出厂年的彩色徽章（0-10 绿 / 10-20 黄 / 20+ 红）
- [x] **URL 同步全部筛选状态**：可分享一个特定查询结果
- [x] **键盘导航**：`/` 聚焦，`Esc` 清空
- [x] **历史登记后续号**可点击查询
- [x] **机型类别组合**：预置"宽体+窄体"、"宽体+货机"选项
- [x] **桌面端两列**：屏幕宽 ≥1000px 时卡片两列展示
- [x] **最近查询**：localStorage 存最近 10 条
- [x] **航司机队仪表板**：每张卡片"机队↗"按钮 → 弹层展示该航司机型分布、平均机龄、机龄直方图、登记和资料匹配统计
- [x] **机型百科**："百科↗"按钮 → 弹层展示该机型全球分布、Top 10 运营商、地区分布
- [x] **同航司同型号链接**：卡片底部"查看该航司其他 N 架 A350"
- [x] **航司 logo**：每张卡片航司行加 daisycon 小 logo
- [x] **联盟徽章品牌色**：金/蓝/红高对比度 + 图标
- [x] **照片大图模态**：点照片打开 full-screen viewer
- [x] **座位图直链**对应已核实的机型构型
- [x] **列存压缩**：`aircraft.col.json` 16MB → 5MB（gzip 后约 1MB）

### 中期

- [ ] **客舱配置继续补全**：已识别航司的商用飞机覆盖率目标为 85%+
- [ ] **多语言**：加英文 UI
- [ ] **退役历史时间线**：基于历史快照差分

### 不打算做

- ❌ **每架飞机的实际座位图**：现实不可行（数据闭源 + 频繁变化）
- ❌ **订票 / 选座**：与本工具定位相反
- ❌ **用户登录 / 评论**：会引入数据 / 合规负担

## 5. 维护节奏

- **每月**：GH Actions 自动跑数据刷新
- **按需**：复核 Issue 的来源并更新登记或客舱源表
- **季度**：人工审一遍文档与数据规模
- **长期无提交时**：GitHub 会在公开仓库 60 天无活动后停用定时工作流；收到提醒后在 Actions 中重新启用 `Build and Deploy`
